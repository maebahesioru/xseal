# xseal for Android

X（Twitter）の投稿欄やDMの文を、その場で別の文字列に変換してから出すためのアプリ。
画面に常駐する丸いボタン（**xo**）を押すだけで変換・復号できる。

- 中身は Chrome / Firefox 拡張の `xseal` と**同一のコア**（`core.js` をヘッドレス WebView で実行）。
  そのため、拡張で作った封筒も、このアプリで作った封筒も、互いに読める。
- 形式は `xo`（鍵なし・base2048 + 算術符号）。**暗号ではなく難読化**なので、誰でも元に戻せる。

## 入れる

```bash
# USB デバッグを有効にした端末を繋いで
adb install -r xseal-android.apk
```

APK を端末にコピーして開いてインストールしてもよい（提供元不明のアプリを許可する必要あり）。

## 初回設定（3ステップ）

アプリを開いて上から順に押す。

1. **① オーバーレイ権限を許可** … 他アプリの上にボタンを出すため
2. **② アクセシビリティを有効にする** … 投稿欄に直接書き込むため
   （設定 → ユーザー補助 → インストール済みのアプリ → xseal → オン）
3. **③ 画面にボタンを出す** … 常駐ボタンが出る（通知も1本立つ）

アクセシビリティを許可しない場合でも動く。その場合は「クリップボードにコピー →
長押しで貼り付け」の2タップ運用になる。

## 使い方

1. X アプリの投稿欄をタップして、本文を打つ
2. 画面の **xo** ボタンを押す → **封印**
3. 投稿欄の中身が封筒（`xo` で始まる文字列）に置き換わる → そのまま投稿

読み手側：

1. 封筒が書かれた投稿を開く
2. 本文を長押ししてコピー（または投稿欄に貼り付け）
3. **xo** → **復号**

複数の封筒が混ざった文でも、全部まとめて平文に戻る。

## ボタンの操作

- **ドラッグ** … 好きな位置へ移動（位置は記憶される）
- **タップ** … パネルを開く／閉じる
- パネルの **閉じる** でパネルだけ閉じる。常駐ボタンを消すときはアプリの「ボタンを止める」

## 仕組み

| 層 | 中身 |
|---|---|
| 変換 | 静的 Huffman / deflate / 次数1算術符号のうち最小のもの（自動選択） |
| 文字化 | base2048（1文字 ≒ 11bit） |
| 封筒 | `xo` + 本文。ヘッダ1バイトのみ |
| 実行 | WebView 上で `core.js`（拡張と同一コード） |
| 入力欄への書き込み | AccessibilityService の `ACTION_SET_TEXT` → 読戻しで検証 |

実測（`テスト投稿です。これはAndroid版の動作確認。` = 22文字）:
**26重みの封筒**になり、復号すると完全に元へ戻る。

## ビルド

Gradle を使わない手ビルド。

```bash
sudo pacman -S --needed jdk17-openjdk      # JDK 17 が必要
./build.sh
```

`build.sh` がやること: `core.js` を `assets/` へコピー → `aapt2 compile` → `aapt2 link`
→ `javac` → `d8` → zip で `classes.dex` 追加 → `zipalign` → `apksigner`（初回は `debug.keystore` を自動生成）。

- Android SDK は `~/android-sdk`（`ANDROID_SDK_ROOT` で変更可）に
  `cmdline-tools/latest` / `platform-tools` / `platforms;android-34` / `build-tools;34.0.0` が必要。
- **注意**: `d8` は PATH 上の `java` を使う。JDK 8 が先に来ていると
  `UnsupportedClassVersionError` で落ちるので `build.sh` は `PATH` の先頭に JDK 17 を入れている。

## 検証済み / 未検証

**検証済み（Waydroid = Android 14 の実機イメージ上で実施）**
- APK のビルドとインストール（`aapt2 dump badging` で package `app.xseal` / minSdk 26 / targetSdk 34、署名検証OK）
- アプリ起動（`topResumedActivity=app.xseal/.MainActivity`、クラッシュログなし）
- **封印 → 復号の往復**: `hello_world`（10重み）→ `xoÇVʎǵïðzðø`（10字、`重み: 10 / 280`）→ `hello_world`
- **オーバーレイ**: 権限許可後にホーム画面へ常駐ボタンが出る、タップでパネル（封印/復号/閉じる）が開く、
  `dumpsys activity services` で `OverlayService isForeground=true`
- `core.js` と `assets/index.html` のブリッジ単体テスト: 22字 → 26字封筒、往復一致、
  複数封筒の一括復号（`日本産の魚介類は終わってます`）、プロファイル列挙

**未検証**
- 本物の X アプリの投稿欄で `ACTION_SET_TEXT` が通るか（通らなければ自動でクリップボード経由になる）
- 実端末でのバッテリー最適化によるサービス停止（必要なら xseal を「最適化しない」に）
- Android 8〜13 での見た目（検証は API 34 のみ）

## 限界

- 暗号ではない。鍵が無いので、形式を知っていれば誰でも戻せる。
- 文字を変換するだけなので、**変換後の本文をスクショで通報されれば防げない**。
- 1ツイートの重み上限（280）は拡張と同じ。長文は分割が要る（この版は分割UIなし）。
- 復号は「本文中の封筒」を対象にする。画像や動画の中身は対象外。
